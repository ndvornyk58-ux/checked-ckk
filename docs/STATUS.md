# Статус реализации

Фиксируются только реально работающие и покрытые тестами функции.

## PHASE 3 — GUI ✅ (16.11.2026)

**Оболочка**: главное окно с боковой навигацией, выбор и создание проектов, состояние хранилища
(открыто/заблокировано), неблокирующие уведомления, горячие клавиши (Ctrl+1…4 — разделы,
Ctrl+F — поиск, Ctrl+I — импорт, F5 — обновить, Delete — удалить выбранное).
Тёмная (по умолчанию) и светлая темы из общих дизайн-токенов; палитра Qt строится из тех же токенов.

**Хранилище**: при первом запуске — выбор защиты ключа (системное хранилище или мастер-пароль),
далее — разблокировка; вычисление ключа из пароля выполняется в фоне. Блокировка «на ходу»:
метаданные остаются доступны, действия со значениями — нет.

**Обзор**: спектр статусов (доли всех записей, клик по легенде открывает отфильтрованный список),
8 показателей, распределение по критичности, график операций за 14 дней, последние операции,
приглашение к импорту для пустого проекта.

**Cookies**: таблица с ленивой подгрузкой страниц (в памяти — только просмотренные строки),
поиск с задержкой ввода, фильтры по статусу/критичности/сроку/Secure/SameSite, группировка по
доменам, сортировка по имени/домену/сроку, панель деталей с находками (причина, риск,
рекомендация), раскрытие значения по запросу, копирование с автоочисткой буфера через 30 с,
редактирование с повторной проверкой, отметка тестовой сессии, удаление, массовые действия
«ко всем по фильтру», контекстное меню.

**Импорт**: перетаскивание файлов и папок, выбор через диалоги, очередь без дубликатов,
предпросмотр в фоне (формат, уверенность, первые записи, проблемные строки), политика дубликатов,
повторный импорт, проверка после импорта, прогресс по байтам, отмена с полным откатом,
отчёт по каждому файлу.

**Настройки**: тема, смена мастер-пароля, блокировка, переименование и удаление проекта,
очистка значений, папка данных.

### Результаты проверок
- ruff, mypy, import-linter (4/4) — чисто; pytest — 191 тест, из них 13 GUI-тестов (pytest-qt, offscreen);
  покрытие 93 %.
- Тест «нет кнопок без действия» обходит все кнопки и действия главного окна и всех диалогов.
- Визуальная проверка по скриншотам (`docs/screenshots/`): найдены и исправлены светлая палитра
  в тёмной теме у HTML-панели и флажков, неверный итог «Все домены», двойная подсветка в навигации,
  обрезанные колонки, устаревший предпросмотр после импорта.

### Найдено и исправлено в ходе фазы
- «Сбросить фильтры» не перезагружал таблицу: сигнал `clicked(bool)` передавал `False` в параметр
  `reload`. Закреплено тестом.
- Поле модели `sort` перекрывало виртуальный метод Qt `QAbstractItemModel.sort` (найдено mypy).
- Из фонового потока изменялся текст виджета — недопустимо в Qt; прогресс идёт только через сигналы.
- Уведомление после закрытия окна обращалось к удалённому виджету.

### Известные отклонения
- **Отзывчивость**: максимальная пауза главного потока во время импорта 30 000 записей — 110 мс
  при цели 50 мс. Причина — общий GIL у фонового потока и интерфейса на однопроцессорной машине.
  Решение в PHASE 5: разбор файлов в отдельном процессе. Тест сейчас ловит зависания > 250 мс.
- Визуальная приёмка на Windows не проводилась (среда разработки — Linux без дисплея).

## PHASE 2 — Core Engine ✅ (16.11.2026)

**Парсеры** (`app/parsers`) — потоковые, файл не загружается в память целиком:
- Netscape (`#HttpOnly_`, комментарии, CRLF, BOM, сессионные cookies);
- JSON: массив (расширения браузеров, Selenium) — потоково; Playwright `{"cookies": [...]}`; одиночный объект;
- JSON Lines; CSV (разделитель `, ; TAB |` по заголовку, кавычки, многострочные значения); нативный CIPX;
- единое сопоставление полей для всех форматов с именованными полями (синонимы, булевы, SameSite, сроки);
- автоопределение формата с оценкой уверенности и предупреждением о неоднозначности;
- распознавание повреждённых файлов: двоичные, SQLite, ZIP/gzip/PDF, не UTF-8, пустые, обрезанные JSON.

**Импорт** (`ImportService`): файлы и каталоги (рекурсивно), предпросмотр без записи в БД,
прогресс (файлы/байты/записи), отмена с полным откатом, политики дубликатов skip/keep/replace,
распознавание повторного импорта по SHA-256, ошибки по строкам, статусы файлов
imported/partial/failed/already_imported, журнал операций.

**Валидация** (`ValidationService` + `app/rules`): 7 групп правил корректности
(RFC 6265/6265bis, PSL, префиксы `__Secure-`/`__Host-`, SameSite=None, Partitioned, лимиты размеров,
400 дней, дубликаты) и 5 групп правил безопасности (Secure, HttpOnly, SameSite, срок жизни,
область видимости, конфликты имён, JWT `alg=none`, права в значении, слабые идентификаторы сессий).
Статусы VALID/EXPIRED/INVALID/WARNING/SECURITY_ISSUE/UNKNOWN с точной причиной у каждой находки.

**Хранилище и безопасность**: AES-256-GCM для каждого значения, ключ данных обёрнут ключом из
системного keyring или scrypt от мастер-пароля, смена способа защиты, HMAC значений для
дубликатов, журналы с редактированием секретов (стек ошибок сохраняется, но тоже редактируется).

**Запросы** (`CookieService`): keyset-пагинация по 4 ключам сортировки, поиск по подстроке
(FTS5 trigram), фильтры по статусу/критичности/сроку/флагам/пакету, статистика для Dashboard,
детали с находками, раскрытие значения с записью в журнал операций, редактирование с
перешифровкой, удаление, очистка значений с сохранением метаданных.

**CLI**: `key init/status`, `project list/create/delete`, `import`, `validate`, `stats`, `list`.

### Результаты проверок
- ruff, ruff format, mypy (strict для domain/rules/parsers/services) — чисто; import-linter — 4/4.
- pytest — 173 теста; покрытие 96 % (domain 91–100 %, parsers 92–100 %, rules 93–100 %).
- Тест-ловушка: маркер из импортируемого файла не найден в журналах, в байтах файла БД и WAL,
  в отчётах об ошибках и журнале операций.
- Производительность (контейнер: 1 CPU, 3,9 ГБ RAM):

| Записей | Импорт | Проверка | Страница таблицы | Поиск | Пик памяти |
|---|---|---|---|---|---|
| 100 000 | 11,6 с | 20,3 с | 4,9 мс | 12 мс | 89 МБ |
| 500 000 | 63,9 с | 127,7 с | 6,6 мс | 55 мс | 90 МБ |

Память не растёт с объёмом данных. Узкое место — проверка (~4–5 тыс. записей/с в одном
процессе); распараллеливание запланировано на PHASE 5.

### Найдено и исправлено в ходе фазы
- Записи, прочитанные до места повреждения файла, терялись (оставались в буфере чанка).
  Исправлено; закреплено тестом `test_partial_file_keeps_records_before_corruption`.
- `csv.Sniffer` ненадёжен на строках разной длины — заменён детерминированным определением
  разделителя по заголовку.
- Оценка энтропии завышалась для однообразных значений («aaaa…») — учитывается число различных символов.

### Известные ограничения
- Trigram-поиск работает от 3 символов; более короткие запросы выполняются через LIKE (медленнее).
- Значения сроков в миллисекундах не преобразуются автоматически — запись отклоняется с подсказкой.
