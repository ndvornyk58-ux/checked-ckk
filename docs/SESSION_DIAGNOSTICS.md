# Проверка тестовой сессии на своём сайте

Session Diagnostics отправляет **ваши тестовые** cookies на **ваш** адрес и проверяет, отвечает ли сервер
так, как отвечает вошедшему пользователю. Ограничения (ADR-0004) встроены в код: чужие домены
проверить нельзя, пакетной проверки нет, cookies уходят только те, что вы отметили как тестовые.

## 1. Подготовьте адрес на сайте

Нужна страница или API, которая отвечает по-разному вошедшему и не вошедшему пользователю:
`/api/me`, `/account`, `/profile`. Запомните, чем отличаются ответы — это и будут **маркеры**:

| Признак | Пример для вошедшего | Пример для не вошедшего |
|---|---|---|
| Код ответа | 200 | 401, 403 или 302 |
| Текст в ответе | ваш логин, `"authenticated": true` | «Войти», «Login» |
| Заголовок Location | — | `/login` |

Одного кода 200 недостаточно: многие сайты отвечают 200 и страницей входа. Программа требует
хотя бы один текстовый маркер.

## 2. Получите тестовые cookies

Войдите на сайт **тестовой учётной записью**, откройте DevTools (F12) → Application → Cookies и
экспортируйте cookies своего домена в JSON любым расширением (или через «Copy as cURL» и вручную).
Импортируйте файл: раздел **Импорт** или `python main.py import cookies.json --project my-site`.

## 3. Добавьте адрес и подтвердите владение доменом

**В интерфейсе:** раздел **Диагностика** → «Добавить адрес…» → адрес `https://ваш-домен/api/me` и маркеры.
Программа покажет строку подтверждения.

**В командной строке:**
```bash
python main.py diag add https://ваш-домен/api/me --project my-site --contains "ваш_логин" --not-contains "Войти"
```

Разместите на сайте файл `https://ваш-домен/.well-known/cookie-inspector-verify.txt`, содержащий
показанную строку `cookie-inspector-verify=…`, и нажмите «Проверить владение»
(или `python main.py diag verify https://ваш-домен/api/me --project my-site`).

Требования к файлу: отдаётся по HTTPS напрямую (без редиректа), код 200. После проверки файл
можно удалить; подтверждение действует 30 дней.

## 4. Отметьте тестовую cookie и проверьте

Раздел **Cookies** → выберите сессионную cookie сайта → «Отметить как тестовую сессию».
Затем в **Диагностике** — «Проверить сессию». CLI:
```bash
python main.py list --project my-site            # найти ID cookie
python main.py diag mark 12 --project my-site
python main.py diag run https://ваш-домен/api/me --project my-site
```

Результат: «совпало» — сервер принял cookie как действующую сессию; «не совпало» — показано,
какой именно маркер не выполнен (код, текст, Location).

## 5. Проверка выхода из аккаунта («до/после»)

Самая полезная проверка безопасности: аннулирует ли сервер сессию при выходе.

1. «Проверить «до»» — сессия должна подтвердиться.
2. Выйдите из аккаунта на сайте в браузере.
3. «Проверить «после»».

Если после выхода сессия всё ещё принимается — сервер не аннулирует сессии, и украденная cookie
остаётся рабочей. CLI: `diag run … --phase before`, затем `diag run … --phase after --pair <ID>`
(код возврата 3 — найдена проблема).

## Что сохраняется

Код ответа, время, результаты маркеров, имена отправленных cookies и имена cookies, которые сервер
попытался установить. **Не сохраняются** тело ответа, значения cookies и значения `Set-Cookie`.
