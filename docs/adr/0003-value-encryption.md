# ADR-0003. Шифрование значений cookies

**Статус:** принято (PHASE 1), реализация — PHASE 2

**Решение.** Каждое значение шифруется AES-256-GCM случайным 96-битным nonce; в БД
хранится nonce‖шифротекст‖тег. Ключ данных (DEK) генерируется один раз и хранится
обёрнутым в `key_store`. Ключ-обёртка (KEK): по умолчанию из системного keyring
(Windows Credential Manager / macOS Keychain / Secret Service); при недоступности keyring
или по выбору пользователя — scrypt от мастер-пароля. `key_check` позволяет отличить
неверный пароль от повреждённых данных.

Для поиска дубликатов без расшифровки хранится HMAC-SHA256 значения на отдельном ключе,
выведенном из DEK (HKDF). Хранить простой хеш нельзя: короткие значения подбираются по словарю.

Метаданные (имя, домен, путь, флаги, срок) не шифруются: по ним идут поиск и аудит,
и сами по себе они не дают доступа к сессии.

**Последствия.** Потеря ключа = потеря значений (метаданные и отчёты остаются). Пользователь
предупреждается при настройке; поддерживается экспорт ключа в резервную копию по паролю.
