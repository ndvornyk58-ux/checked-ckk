# ADR-0001. Слоистая архитектура с механической проверкой границ

**Статус:** принято (PHASE 1)

**Контекст.** ТЗ требует не смешивать GUI и бизнес-логику, не дублировать логику и позволить
переносить модули на другие реализации. В больших desktop-проектах эти правила обычно
разрушаются постепенно, через «один удобный импорт».

**Решение.** Семь слоёв (gui → workers → services → infrastructure → parsers → rules → domain),
зависимости только вниз. Границы описаны контрактами import-linter в `pyproject.toml` и
проверяются тестом. Сборка зависимостей — только в `app/bootstrap.py`.

**Последствия.** Любой модуль ниже GUI тестируется без Qt; замена хранилища или парсера не
затрагивает интерфейс. Цена — немного больше «проводки» в bootstrap.
